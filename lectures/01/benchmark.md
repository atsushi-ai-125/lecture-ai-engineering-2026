# 発展課題: 応答時間・トークン数の比較

`app/benchmark.py` は、同じ質問を複数のGeminiモデルへ独立に送り、回答と計測結果を表示・CSV保存します。既存の `app/ask.py` の対話と会話履歴は変更しません。

## 単一の回答しか出ない場合

| 実行コマンド | 動作 |
|---|---|
| `uv run python -m app.ask "質問"` | 単一モデルとの対話。1つの質問に1つの回答を表示する |
| `uv run python -m app.benchmark` | 比較実験の計画を表示する。APIは呼ばない |
| `uv run python -m app.benchmark --run` | 確認後、JSONに設定した質問を各モデルに送り、回答と計測結果を表示する |
| `uv run python -m app.benchmark --interactive --run` | ターミナルで入力した質問を、確認後に各モデルへ送る |

比較実験では、プロンプトに「複数のモデルで答えて」と書く必要はありません。計画に表示されるモデル数と質問数を確認してください。JSONの初期設定は「2モデル × 3質問 × 1回」です。この場合、正常完了すると `[1]` から `[6]` までのモデル名付きの結果と「完了: 6/6リクエスト」が表示されます。異なるモデルが同じ回答を返すこともあるため、回答文だけでなくモデル名と件数を確認します。

回答は順番に表示され、初期設定では次の送信まで15秒待ちます。途中でエラーが出た場合は停止するため、成功した回答が1件だけになる場合もあります。最後の完了件数、エラー表示、CSVの `status` と `error_code` を確認してください。

## 実験前にモデルと無料枠を確認する

2026-10-21に確認した[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)では、`gemini-3.5-flash-lite` と `gemini-3.1-flash-lite` のStandardの入力・出力にFree Tierの記載があります。設定ファイルにはこの2つを候補として入れています。ただし、現在のキーでの利用可否や無料枠の残量は、このプログラムから判定できません。モデル名だけで無料になるとは限りません。

1. [Google AI StudioのAPI Keys](https://aistudio.google.com/apikey)で、Codespacesの `GEMINI_API_KEY` に対応するプロジェクトを確認します。キーそのものはターミナルに表示しません。
2. [公式レート制限ページ](https://ai.google.dev/gemini-api/docs/rate-limits)の「View your active rate limits in AI Studio」から、そのプロジェクトの使用階層、モデル別のRPM・TPM・RPDと使用量を確認します。
3. 料金表のFree Tier欄と照合して利用するモデルを選び、`app/benchmark.json` の `models` を変更します。利用可能な2モデルを確認できない場合は、確認できた1モデルで始めてください。有料モデルへ自動で切り替える処理はありません。

有料プロジェクトでは候補モデルも課金対象になり得ます。出力・思考の長さは実行前に確定できないため、金額を推測して無料と断言することはできません。このプログラムではモデル一覧取得や事前の試し呼び出しを行わず、生成リクエストだけを送ります。

## Codespacesでのコマンド

リポジトリのルートで実行します。初めの2つはGemini APIを呼びません。

```bash
# 設定と実行予定の6リクエストを表示するだけ（APIキー不要）
uv run python -m app.benchmark

# モックによる動作確認（既存の会話機能も含む）
uv run pytest -q

# AI Studioで確認後に実測する。確認文に yes と入力すると開始する
uv run python -m app.benchmark --run
```

通常起動では計画の表示だけで終了します。`--run` 指定時も、モデル・回数・課金リスクを表示し、`yes` が入力されるまでAPIクライアントを作りません。空入力・EOF・Ctrl+Cでは開始しません。APIキーは既存の `app/config.py` を通じて環境変数から取得します。

### ターミナルで質問を入力する

```bash
uv run python -m app.benchmark --interactive --run
```

質問を1行ずつ入力し、最後に何も入力せずEnterを押してください。例えば1問だけ比較する場合は次の流れです。

```text
[質問1] 機械学習の過学習とは何ですか。200字以内で説明してください。
[質問2] （何も入力せずEnter）
計画: 2モデル × 1質問 × 1回 = 最大2リクエスト …
…モデル名・生成設定・料金リスクを表示…
上記のモデル・回数・料金リスクを確認して実行しますか？ [yes/いいえ]: yes
```

入力した質問でJSONの質問一覧を置き換えます。モデル・間隔・繰り返し回数は既存の設定を使います。1問なら既定の2モデルで2リクエスト、3問なら6リクエストです。質問は入力順に `input_1`、`input_2` … というIDと「自由入力」という種類でCSVに保存されます。設定ファイル自体は書き換えません。

空行は質問入力の完了を意味します。質問を入力せず空行にした場合や、`exit`／`quit`／`終了`、EOF、Ctrl+Cで中止した場合はAPIを呼びません。入力途中の中止はそれまでの質問も破棄します。`--run` を付けず `--interactive` だけ指定すると、入力した質問の実験計画を確認するだけで終了します。

質問をまとめて受け付けた後に、各モデルの回答・計測結果を順番に表示します。各リクエストは独立しており、前の質問や回答は引き継ぎません。

次の例もAI Studioで利用条件を確認してから実行してください。

```bash
# 設定のモデルを上書きし、送信間隔を30秒にする（6リクエスト）
uv run python -m app.benchmark --models gemini-3.5-flash-lite gemini-3.1-flash-lite --interval 30 --run

# 2回ずつ比較する計画を確認する（12リクエスト。まだ送信しない）
uv run python -m app.benchmark --repeat 2

# 保存先を指定する。既存ファイルは上書きしない
uv run python -m app.benchmark --output benchmark_results/experiment1.csv --run

# 別の実験設定で計画を見る
uv run python -m app.benchmark --config app/benchmark.json
```

設定ファイルの `questions` は、識別用の `id`、種類を表す `category`、送信する `text` の組です。初期設定は「事実確認」「説明」「推論」の3種類です。各モデルに同一の文面を送り、前の質問・回答は一切追加しません。質問に秘密情報を含めず、APIキーを設定ファイルに保存しないでください。

`repeat` は各モデルと質問の組み合わせの試行回数、`interval_seconds` は前の応答完了から次の送信までの待機時間です。初期値15秒は実験用の設定であり、無料枠の制限値や成功を保証する値ではありません。引数の `--models`・`--repeat`・`--interval` はJSONより優先します。既存の対話用 `AIE_MODEL` は比較スクリプトには適用しません。

## 計測とCSV

`time.perf_counter()` をAPI呼び出しの直前と、応答が返った直後（失敗時は例外を受けた直後）に読み、その差を秒で記録します。待機、クライアント作成、表示、CSV保存は含めません。通信、SDK内の処理、サーバーの待ち時間、生成処理は含みます。最初の文字までの時間やモデル内部だけの処理時間ではありません。

CSVは標準で `benchmark_results/日時.csv` に保存します。UTF-8形式で、改行やカンマを含む回答もCSVの引用規則で保存します。1リクエストごとに書き込み・flushするので、途中エラーやCtrl+Cでも完了分が残ります。中断したリクエストは計測未完了のため記録されず、サーバー側の処理が中止されたとも限りません。

| CSVの主な列 | 意味 |
|---|---|
| `model`, `model_version` | 指定モデル名とAPIが返したモデル版 |
| `question_id`, `category`, `question`, `answer` | 質問の識別子・種類・本文と回答 |
| `request_index`, `repeat`, `started_at_utc` | 実行順・何回目の試行か・UTC開始日時 |
| `elapsed_seconds` | API呼び出しの経過秒数 |
| `input_tokens` | `usage_metadata.prompt_token_count` |
| `output_tokens` | `usage_metadata.candidates_token_count` |
| `total_tokens` | `usage_metadata.total_token_count` |
| `thinking_tokens` | `usage_metadata.thoughts_token_count` |
| `generation_config`, `interval_seconds` | 実際に渡した生成設定と待機時間 |
| `status`, `error_code`, `error` | 結果の分類、APIエラーコードと内容 |
| `finish_reason` | `STOP`、`MAX_TOKENS`、ブロック理由など、APIが返す終了理由 |

トークン数は[公式のUsageMetadata](https://ai.google.dev/api/generate-content#UsageMetadata)から取得します。未取得はCSVで空欄、画面では「未取得」です。0と未取得を区別し、合計を足し算で補完することもしません。総トークン数には思考なども含まれるため、入力＋表示回答のトークン数と一致するとは限りません。

`status` は `ok`（回答あり）、`empty`（API応答はあるが回答テキストなし）、`api_error`、`client_error` です。空の回答は理由と取得できたトークン数を残し、成功回答の平均には含めません。通信エラーは種類を記録し、認証情報を含む可能性のある例外本文やURLは保存しません。APIエラー文や回答に使用中のキーが混じった場合も伏せ字にします。

モデル別・質問別・モデル×質問別に平均を表示します。`ok` のうち値を取得できた行だけで計算し、各項目の `n` はその件数です。質問別平均は複数モデルを混ぜた値なので、厳密な比較にはモデル×質問の同じ組を使います。初期設定の各組は1回だけであり、平均もその1回の値です。

## レート制限と結果の考察

[Gemini API公式レート制限資料](https://ai.google.dev/gemini-api/docs/rate-limits)では、主に次の3つで制限します。

| 指標 | 意味 | 今回の計測との関係 |
|---|---|---|
| RPM | Requests Per Minute: 1分あたりのリクエスト数 | 待機時間を長くすると送信頻度を下げられる |
| TPM | Tokens Per Minute: 1分あたりの入力トークン数 | 長い質問ほど入力側の制限を消費しやすい。`total_tokens`をそのままTPMと比較しない |
| RPD | Requests Per Day: 1日あたりのリクエスト数 | 繰り返し回数を増やすと消費が増える。間隔を空けても1日分の消費は減らない |

制限はプロジェクト単位で、モデルや利用階層によって異なります。同じプロジェクトを使う別の実験の消費も考慮します。RPDのリセットは太平洋時間の午前0時です。現在の具体値はAI Studioで確認し、この資料やコードでは推測した上限値を設定しません。

429 `RESOURCE_EXHAUSTED` は制限に達した際の代表的なエラーです。コードはSDKの自動リトライを無効にし、429を含むAPIエラーや通信エラーをCSVへ記録した時点で実験全体を停止します。エラーの内容とAI Studioの使用量から原因を確認し、必要に応じて間隔・質問長・回数を調整します。429だけからRPM・TPM・RPDのどれが原因かは断定できません。エラーまでの時間は成功応答の速さとは比較せず、平均からも除外します。制限を意図的に超える実験は行いません。

### 比較するときに確認する条件

- **回答の長さ**: 説明は都市名だけの回答より長くなる可能性があります。出力トークン数と応答時間を一緒に見ます。短いが不正確な回答を高性能と判断しないよう、回答内容も確認します。
- **生成設定**: 初期値は `temperature=1.0`、`max_output_tokens=1024` です。上限が同じでも実際の回答長は揃いません。`MAX_TOKENS` なら途中で打ち切られた可能性があります。
- **思考設定**: `thinking_level=null` はモデル既定の動作です。モデル間で内部の思考量が揃うとは限りません。対応モデルなら共通の `LOW` 等に変更できますが、同じレベルでも同じ思考トークン数とは限りません。対応範囲は[公式の思考設定資料](https://ai.google.dev/gemini-api/docs/thinking)と各モデルの仕様で確認します。未対応の設定を自動的に変更して再送する処理はありません。
- **通信・混雑**: ネットワーク、接続の再利用、サーバー混雑、モデルの更新で時間は変化します。明示的なキャッシュは使いませんが、サービス内部のキャッシュ等も完全には制御できません。
- **質問・モデルの順序**: 繰り返し → 質問 → モデルの設定順に逐次実行します。後のモデルが時間帯や接続再利用の影響を受ける可能性があります。追加実験を行う場合はモデル順を逆にした条件などを別CSVに記録し、予算・割当量を確認して最小限に留めます。
- **試行数**: 2モデル×3質問×1回は傾向を探す小規模な実験です。ばらつきや一般的な優劣は断定できません。実測前に平均値や最速モデルの結論を作らないでください。

考察では、実際のCSVに基づいて「どの質問で時間・出力・思考が増えたか」「短い質問を多く送る場合と長い質問を送る場合で、どの制限が先に問題になりそうか」「間隔を増やしてもRPDへの対策にならない理由」を説明できます。6回の測定だけでは、実際の上限値や429の発生条件を検証したことにはなりません。

## 実装と検証の範囲

複数モデル・質問・反復、履歴なしの送信、応答と時間・トークン・エラーの記録、CSV、平均、設定可能な間隔、実行前確認、429時の停止を実装しています。新しいライブラリの導入はなく、既存のgoogle-genai・PydanticとPython標準ライブラリを使います。

自動テストではAPIをモックに置き換え、送信の独立性、計測、欠損値、エラー、秘密情報の除去、確認操作、CSV保存を検証します。実APIでの測定値とプロジェクト固有の無料枠は、この実装・モック検証だけでは確認できません。
